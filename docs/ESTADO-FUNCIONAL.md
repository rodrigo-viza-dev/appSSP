# Estado funcional · PrácticasCC

Revisión del 23 de noviembre de 2026, desarrollo hasta el incremento 33. Este documento resume el código actual y distingue implementación, revisión y dependencias pendientes. El plan original conserva diagnósticos históricos que ya se resolvieron.

## Entrega y desarrollo

La presentación está fijada en `avance-2026-10-23-v0.2.0`: web y APK independientes del PC, API dedicada, datos ficticios y credenciales propias. El desarrollo continúa en `desarrollo/post-presentacion-2026-10-23`, con `ssp_test`. Los incrementos 25–33 no reemplazan esa web ni ese APK.

El 13 de noviembre el pooler de Supabase rechazó la conexión a `ssp_test` (`tenant/user not found`). El proyecto se restableció y el 14 de noviembre `/dev/ready` responde con `ssp_test` y la base alcanzable; los recorridos reales del personal, incluidas las metas paginadas, pasaron contra la API ese día.

## Orden para completar el piloto

1. **Revisión móvil real:** teclado, fuente ampliada, Atrás, adjuntos, descarga/compartir PDF y recuperación de borradores tras cerrar la app. El APK ya entregado verifica un avance anterior, no los cambios 25–28. Preparar un candidato nuevo después de estabilizar el siguiente bloque.
2. **Interiores y listas con volumen:** cinco pestañas para los cuatro roles; alumno paginado en sus recorridos principales, personal paginado en aulas, padrón, entregas, notas, tareas docentes, asistencia por días, metas del personal y bitácora de horas del supervisor, administración/reportes/auditoría y comunidad (anuncios, temas y respuestas) por páginas. Quedan selectores de prácticas de otros módulos que aún usan listas completas (metas del alumno, expediente, asignaciones). El resumen de Notas abre la ficha individual para consultar tareas; el libro anterior sigue disponible por API, sin descargarse en esa vista.
3. **Acceso institucional y recuperación:** el acceso Google en web quedó verificado real el 14 de noviembre con el ingreso autorizado del usuario (camino recurrente); faltan la primera vinculación con contraseña SSP y el rechazo de cuenta externa en navegador, y el Android nativo se comprueba con la compilación habilitada (candidata del cierre). SMTP requiere un servicio/cuenta de envío configurada; el endpoint preparado por sí solo no entrega correos. La presentación no ofrece estos accesos como terminados.
4. **Criterios académicos:** confirmar horas por modalidad, jornada, entregas tardías/excepciones, requisitos del expediente, rúbricas, cartas, atribuciones y conservación. Los valores técnicos o ejemplos no constituyen reglamento institucional.
5. **Infraestructura del piloto:** definir almacenamiento y cuotas reales, rol de ejecución de base separado del propietario/migraciones, respaldos y restauración, operación del servidor y acceso a datos. La base actual está autorizada para pruebas ficticias.
6. **Funciones adicionales por alcance aprobado:** GPS/jornadas, push, tiempo real, refresh de sesión, caché completa, sincronización en segundo plano y prórrogas individuales. Requieren desarrollo y, según el caso, configuración de servicios o decisiones institucionales; no están implementadas por tener pantallas o borradores relacionados.

No se declara la aplicación terminada para producción. El avance tiene circuitos funcionales y comprobaciones focales; todavía falta la revisión integral del piloto con los responsables y dispositivos reales.
