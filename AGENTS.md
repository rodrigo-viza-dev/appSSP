# PrácticasCC: instrucciones del proyecto

Leer `docs/CONTEXTO-CODEX.md` antes de continuar y `docs/diseno.md` para las decisiones visuales.

- Proyecto activo después de la migración: `C:\proyectos\appSSP`, accesible desde WSL en `/mnt/c/proyectos/appSSP`.
- Codex puede leer y editar desde WSL. Ejecutar instalación, tipos, pruebas y Expo con Node/npm de Windows, nunca con npm de Linux.
- Usar PowerShell de Windows con directorio de trabajo `C:\proyectos\appSSP`; no ejecutar npm desde la ruta UNC de WSL. No compartir `node_modules` entre Linux y Windows.
- Mantener Expo, TypeScript y Expo Router. Implementar las seis pantallas de `imagenesReferencias/` y conservar la identidad UNSA.
- Granate institucional: `#5E151D`. Ver fuente oficial en `docs/diseno.md`.
- El acceso de demostración no es autenticación institucional. No presentar GPS, persistencia ni notificaciones push como implementados.
- No enviar mensajes al líder del proyecto. Preparar el enlace y el texto para que el usuario los comparta.
- No publicar ni iniciar sesión en cuentas sin autorización. El usuario autorizó preparar la migración, abrir Codex con contexto y preparar lo necesario para compartir un avance; no proporcionó credenciales ni autorizó una publicación concreta.
- Usar Git de Windows para operaciones que escriban metadatos del repositorio después de migrar.
